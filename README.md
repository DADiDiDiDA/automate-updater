# 自动化更新器 · AutomateUpdater

> 批量检测并更新本机那些「从 GitHub 下载的绿色版程序」，支持 git 仓库与 Release 压缩包两类来源，自动处理代理 / 镜像，覆盖前自动备份。

一个带玻璃质感的 Windows 桌面程序，与姊妹项目 [日常检查器](https://github.com/DADiDiDiDA/daily-checker) 共用同一套 PySide6 UI 框架。

| 项目 | 说明 |
| --- | --- |
| 平台 | Windows 10 / 11 |
| 技术栈 | Python 3 · PySide6 · pillow · PyInstaller（单文件 exe，便携） |
| 当前版本 | **v1.6.12** |
| 仓库 | [DADiDiDiDA/automate-updater](https://github.com/DADiDiDiDA/automate-updater) |
| 外部依赖 | `git`（仓库类程序）、`7-Zip` 或 `py7zr`（`.7z` 包） |

## 它解决什么问题

一堆从 GitHub 下的绿色版程序散在几个文件夹里，逐个开仓库页看有没有新版很麻烦。本程序把「检查根目录」里的每个子文件夹当成一个待更新程序，自动识别它的来源、比对本地与远端版本、下载替换，并保留用户数据目录。

- 程序本体是单文件 exe，**便携**：配置与记录写在 exe 同目录，整个文件夹可随意搬走。
- 重复双击不会再开第二个窗口，而是把已有窗口叫到前面（单实例）。
- 打开后**每天只自动检查一次**：当天已检查则直接离线展示上次结果，不会每次开程序都把网络跑一遍；手动「立即检查」随时可用。

## 快速开始

1. 下载 `AutomateUpdater.exe`，双击运行。
2. **设置 → 检查文件夹**：添加你的根目录（默认 `D:\Automate`），需要的话排除内部子文件夹、调整扫描深度。
3. 按 `F5` 检查。列表里会显示 `旧版本 → 新版本`、发布说明与可更新状态。
4. 右键单个程序「立即更新」，或在设置里选择发现新版本时的自动策略。
5. 认不出 GitHub 仓库的程序显示「未绑定」，右键「绑定仓库」填 `owner/repo` 即可启用。

## 核心概念

| 概念 | 说明 |
| --- | --- |
| **检查根目录 (roots)** | 可添加任意多个；每个根目录可单独排除内部子文件夹（只写文件夹名）、设扫描深度、开关启用 |
| **两类来源** | `GIT`：git 克隆仓库，按落后提交数比较并 `merge --ff-only`；`Release`：调 GitHub API 取最新 tag 与压缩包 |
| **锚点文件** | `interface.json`、`MAA.exe`、`BetterGI.exe` 这类能标识程序根目录的文件。解压后靠它剥掉压缩包里多余的多层目录，单层包和 `包名/包名/文件` 两层包都能正确定位 |
| **版本识别** | 内置 7 款程序有精确规则（`json` 字段 / exe 版本 / 文本正则 / 本程序记录）；读不到时可右键「手动标记本地版本」 |
| **保留名单** | 覆盖前保留的用户数据文件夹（默认关键词 `User / config / save / profiles / settings`）；名字含关键词即保留，只匹配第一层文件夹。可全局设置，也可按程序单独定制 |
| **下载文件筛选** | 同一个 Release 有 `-full` / `-slim` / `-debug` 等多份 Windows 包时，弹窗让用户选；也可右键填正则长期指定。优先级固定：**用户正则 > 选中的文件 > 自动规则** |

## 主要功能

| 功能 | 说明 |
| --- | --- |
| 来源筛选 | 按「全部 / 有更新 / Git / Release / 失败」筛选，支持搜索 |
| 两级排序 | 基础排序（名称 A→Z / Z→A、体积大→小 / 小→大、最近发布 / 最早发布、最近更新 / 最早更新）+ 特殊规则（有更新最先 / 不额外排序 / Git 优先 / Release 优先）；时间类排序按日期数值比较，同日才应用特殊规则 |
| 版本变化与日志 | 直接显示 `旧版本 → 新版本`；git 显示提交短哈希。展开每行的「日志」看 Release 说明或待拉取的提交记录 |
| 手动标记版本 | 读不到版本号时右键填一个版本，即可正常比对并参与批量更新；通过该标记触发的更新成功后，标记会自动清除，由更新记录接管，重启后不会再误报待更新 |
| 撤销上次更新 | 更新出问题时右键还原到更新前备份（Git 仓库按提交拉取，无备份不适用） |
| 更新排队 | 已有更新任务在跑时再点「更新」会加入队列，当前轮结束后自动继续，不提示冲突 |
| 两种安装方式 | `只保留指定文件夹`（删掉名单外旧文件再解压）/ `直接覆盖`（保留全部旧文件，只替换同名内容） |
| 自动备份 | 覆盖前把整个程序目录备份到 `<根目录>\Cache\_backup\<程序名>_<时间>`，可设保留份数 |
| 更新超时 | 单个程序下载 + 解压总时长超过设定值（默认 10 分钟）自动中止 |
| 占用自动等待 | 程序正在运行或文件被占用时自动暂停、每 3 秒重试，直到释放 / 手动停止 / 最长等待到期（默认 5 分钟）；超时后行按钮变「重试」 |
| 断点续传 | 下载中断保留 `.part` 从断点继续；连续 20 秒无任何数据才判断流，先**在同一条线路**续传重试（最多 3 次），续不上才换下一个加速地址；返回错误页 / 大小不符的线路直接跳过 |
| 静默执行 | 调用 git / tar / tasklist 等子进程时不弹控制台窗口 |
| 单实例 | 只允许一个进程，再次启动唤起已有窗口 |
| 后台常驻 | 关窗最小化到托盘；托盘悬停显示程序名、上次检查时间、新版本数量 |
| 开机自启 | 写当前用户启动项，开机后带 `--tray` 后台静默运行，不弹主界面 |
| 更新策略 | 只通知 / 静默更新后提示 / 完全静默更新 |
| 通知方式 | 系统通知、钉钉机器人、弹出主界面（可多选，钉钉配置在同一可展开项里） |
| 三套皮肤 | 亚克力（玻璃模糊）/ 莫奈（Material You）/ Miuix（澎湃 OS 风格） |
| 明暗 / 毛玻璃 | 跟随系统 / 浅色 / 深色；毛玻璃可关闭（Miuix 不使用毛玻璃，开关自动禁用并说明） |

毛玻璃打开时，主窗口、对话框、下拉菜单、右键菜单用同一套玻璃：弹层出现前先截取它背后**真实画面**再模糊，透出来的不是贴一张壁纸，而是被遮住的窗口内容；关闭后所有面板一起变回不透明纯色。

## 更新是怎么做的

1. **检查**：git 仓库 `fetch` 后比较落后提交数；Release 程序调 GitHub API 取最新 tag、发布说明与资产清单。
2. **更新 Release**：下载（带大小与 `sha256` 校验）→ 解压 → 用锚点文件定位程序根目录 → 备份 → 按安装方式处理（清除名单外旧文件 / 直接覆盖）→ 写入新版 → 更新 `records.json`。任何一步失败都会回滚，绝不写 records、不标「已最新」。
3. **更新 git**：`fetch` + `merge --ff-only`；工作区有未提交改动时不动它，只在列表里标记「跳过」。

## 网络与加速

- **本地代理**：`自动探测`（扫描常见代理端口）/ `手动指定` / `不使用代理`。手动地址**仅支持 `http://`**（如 `http://127.0.0.1:7890`），`socks5://` 不受支持，请在代理软件里另开 HTTP 端口；改完立即生效。
- **GitHub 镜像**：内置 10 个公共镜像，默认开启；设置 → 网络 →「镜像地址 · 管理…」可自己添加反代地址（域名或完整 URL、支持路径前缀）、删除内置项或一键恢复。地址自动补 `https://`、去多余斜杠，重复项与 `github.com` 本身会被挡掉。
- **社区节点**：每天从 [hubporg/ghproxy-next](https://github.com/hubporg/ghproxy-next) 的 `components/nodes.ts` 同步一次 `PROXY_NODES`，与手动列表一起参与测速。抓取走「本地代理 → 官方直连 → 按测速排序的最快线路转发 `raw.githubusercontent.com`」多路径回退，**不要求你开着 GitHub 加速**；整条回退链有 24 秒总时限，失败时保留上次节点。社区节点单独存放，不污染手动列表，设置页可开关 / 立即同步 /「查看…」看全部节点与测速明细。
- **测速**：所有候选每天测速一次，结果（含毫秒数）落盘；「GitHub 镜像地址」对话框按速度从快到慢排列，未响应的排最后标注。设置页「每天自动测速一次」卡片位于网络分组最上方，带开关与「立即测速」按钮；关掉后启动准备流程会跳过两次测速。
- **下载策略**：不看速度，只看「有没有数据进来」。连续 `STALL_TIMEOUT = 20` 秒一个字节都没有才判断流，先在原线路用 `Range` 断点续传重试（最多 3 次），续不上才换候选；靠 `Content-Length` 与 `expect_size` 预检直接跳过返回错误页的镜像。失败原因会写明（`文件大小不符`、`HTTP 403`、`文件校验失败` 等），进度条记住最高值、换源也不回退。

**两类检查，别混为一谈**：

- **准备流程每天只跑一次**（`daily_bootstrap`）：测速内置加速地址 → 同步社区节点 → 全量测速。按日期做闸门，当天做过就跳过；程序常驻跨天时自动补跑。测速由「每天自动测速一次」控制、拉节点由「社区加速节点」控制，关哪个只跳过对应那一步。
- **查版本按间隔反复跑**：启动今天第一次打开会在准备流程之后查一次；之后「后台自动检查更新」按设定间隔（默认 60 分钟）联网查询，窗口开着也查，不受每天一次限制。当天再次打开程序只展示上次结果，不重复跑准备流程。

## 设置说明

设置页分「一般设置 / 关于」两页，所有选项都是「图标 + 标题 + 说明 + 右侧控件」的行式布局。

- **用户界面**：皮肤、明暗模式、毛玻璃开关。
- **后台与自动更新**：关窗最小化到托盘（托盘右键「退出」才真正结束）；开机自启写 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`（值名 `AutomateUpdater`，命令行带 `--tray`，移动文件夹后重新打开一次开关刷新路径）；**后台自动检查更新** + **后台检查间隔**（默认 60 分钟，可输入 5–1440）——程序常驻时按间隔联网查版本（窗口可见时也查），关掉就不再定时查。这个开关**不影响启动首次检查**：今天第一次打开固定跑一遍完整流程。发现新版本时可选 `只通知，不自动更新`（默认）/ `静默更新，完成后提示` / `完全静默更新`。
- **通知方式**：系统通知 / 钉钉机器人 / 弹出主界面可多选；勾选钉钉后同卡片展开 Webhook、加签密钥与「发送测试」。
- **更新策略**：安装方式、默认保留文件夹关键词（一键开关 + 自定义补充；默认 `User / config / save / profiles / settings`；名字含关键词即保留，只匹配第一层文件夹；仅「只保留指定文件夹」模式生效）、单程序保留定制（行右键 →「更新时保留的文件夹…」，可一键「跟随全局」）、单个程序更新超时、文件被占用时自动等待、覆盖前自动备份与保留份数。
- **检查文件夹**：添加根目录后点「排除…」逐行填写要跳过的子文件夹；列表行右键也能直接排除。
- **网络**：见上节。

> 说明：v1.6.7 曾移除「检查间隔」下拉，v1.6.10 以「后台检查间隔」形式加回（只管常驻时的定时查版本，不影响准备流程的每天一次闸门）。`slow_switch` / `stall_policy` / `min_speed_kbps` 仍是历史遗留，升级时自动清理。

## 托盘与快捷键

- 悬停提示：`自动化更新器 / 上次检查：x 分钟前（22:14）/ N 个程序有新版本`；有新版本时图标右上角是带白描边的红色小圆点（只提示「有待处理」，不写数字，图标维持满幅 20px）。
- 右键菜单：打开主界面、打开设置、立即检查更新、静默更新（N）、停止当前任务、开机自动启动、退出。

| 快捷键 | 作用 |
| --- | --- |
| `Ctrl+1 / 2 / 3` | 首页 / 程序 / 设置 |
| `F5` | 重新检查 |
| 右键列表行 | 更新 / 撤销 / 绑定仓库 / 打开 GitHub 仓库 / 手动标记版本 / 下载文件筛选 / 保留文件夹 / 排除文件夹 |

双击列表某一行 = 打开该程序所在文件夹。

## 配置与数据文件（便携）

| 文件 | 内容 |
| --- | --- |
| `config.json` | 全部设置、根目录、镜像与测速结果、程序定制（**含钉钉凭证，已加入 `.gitignore`**）。exe 同目录；目录不可写时退回 `%APPDATA%\AutomateUpdater` |
| `records.json` | 版本记录、更新时间、上次检查时间，以及供离线还原用的 `snapshot` 快照（启动先离线铺列表；更新成功或扫描完成会刷新它） |
| `crash.log` | Qt 事件循环异常的兜底日志 |

配置采用「默认值 + 归一化升级」加载，旧版本字段自动兼容/清理。整个文件夹可随意复制或移动，配置跟着走。

## 从源码运行 / 重新打包

```powershell
pip install PySide6 pillow pyinstaller
python app.py
python app.py --tray          # 后台静默启动（开机自启用这个）
python -m PyInstaller AutomateUpdater.spec --noconfirm --clean
```

依赖：`PySide6`、`pillow`；`.7z` 包可选 `py7zr` 或本机 7-Zip。`build/`、`dist/`、`_test/`、`config.json`、`records.json` 均为本地产物，不入库。

## 已知限制

- `.7z` 包需要 `py7zr` 或本机安装 7-Zip；都没有时该程序会提示「解压失败」。
- 未绑定的程序（没有 GitHub 仓库）不会被更新，只做提示。
- 程序正在运行时会被跳过（或按设置自动等待），避免文件占用。
- 系统通知依赖 Windows 通知中心；关闭「专注助手 / 勿扰」才能看到。
- 体积排序统计的是本地目录大小（跳过 `.git`），首次扫描会略微增加耗时。
