# 自动化更新器

一个带玻璃质感的 Windows 桌面程序，用来批量检测并更新本机那些「从 GitHub 下载的绿色版程序」。
支持 git 克隆仓库与 Release 压缩包两类，自动处理代理/镜像，覆盖前自动备份，可以常驻托盘定时检查。

## 双击即用

- 程序本体：`D:\玩机工具\更新\AutomateUpdater.exe`（单文件，首次启动约 2–4 秒）
- 配置/记录：同目录 `config.json`、`records.json`（便携，随文件夹搬走）
- 源码目录：`D:\玩机工具\更新\AutomateUpdater\`

打开后会自动检查一次更新（每天只自动执行一次，当天已检查则直接显示上次结果），列出有新版本的程序、版本变化和更新日志。重复双击不会再开第二个窗口，而是把已有窗口叫到前面。

## 主要功能

| 功能 | 说明 |
| --- | --- |
| 多检查文件夹 | 可添加任意多个根目录，每个根目录可单独排除内部子文件夹（如 `My-maawork`、`Cache`） |
| 两类来源 | `GIT`（git 克隆仓库，按提交数比较并 fast-forward）与 `Release`（GitHub 发布压缩包） |
| 来源筛选 | 按「全部 / 有更新 / Git / Release / 失败」筛选，支持搜索 |
| 两级排序 | 基础排序（名称 A→Z / Z→A、体积大→小 / 小→大、最近发布 / 最早发布、最近更新 / 最早更新）+ 特殊规则（有更新最先 / 不额外排序 / Git 优先 / Release 优先） |
| 版本变化 | 直接显示 `旧版本 → 新版本`；git 仓库显示提交短哈希 |
| 手动标记版本 | 程序目录里读不到版本号时，右键「手动标记本地版本」填一个版本，就能正常比对并参与批量更新 |
| 撤销上次更新 | 更新出问题时右键「撤销上次更新」，自动还原到更新前的备份（Git 仓库按提交拉取，无备份不适用） |
| 更新排队 | 已有更新任务在跑时再点「更新」，会加入待更新队列，当前轮结束后自动继续，不再提示冲突 |
| 更新日志 | 展开每一行的「日志」：Release 显示 GitHub 发布说明，git 显示将要拉取的提交记录 |
| 两种安装方式 | `只保留指定文件夹`（删掉旧的无关文件再解压新版）/ `直接覆盖`（全部旧文件保留，只替换同名内容），设置里随时切换 |
| 按程序定制保留 | 右键「更新时保留的文件夹…」可为单个程序勾选要保留的子文件夹，覆盖全局设置 |
| 自动备份 | 覆盖前把整个程序目录备份到 `<根目录>\Cache\_backup`，可回滚 |
| 右键菜单 | 立即更新、撤销上次更新、绑定仓库、打开 GitHub 仓库、手动标记本地版本、下载文件筛选、更新时保留的文件夹、打开文件夹、复制路径、排除此文件夹 |
| 下载文件筛选 | 同一个 Release 里有多份安装包（-full / -slim / -debug 等）时会先问你要哪一个，不会拄「体积最大」猜；也可右键「下载文件筛选…」填正则长期指定，优先级：**用户正则 > 选中的文件 > 自动规则** |
| 更新超时 | 单个程序下载 + 解压总时长超过设定值（默认 10 分钟）自动中止 |
| 占用自动等待 | 更新时若程序正在运行或文件被占用，自动暂停并每 3 秒重试，直到释放 / 手动停止 / 最长等待到期（默认 5 分钟）；超时后行按钮变「重试」 |
| 断点续传 | 下载中断后保留已传部分并从断点继续；连续 20 秒没有任何数据才判定断流，先在**同一条线路**上续传重试（最多 3 次），续不上才换下一个加速地址；返回错误页/大小不符的线路直接跳过 |
| 静默执行 | 检查与更新时调用的 git / tar 等命令都不弹控制台窗口 |
| 单实例 | 只允许一个进程；再次启动会唤起已有窗口 |
| 网络自适应 | 代理可选自动探测 / 手动指定 / 不使用；每天一次依次：内置加速地址测速 → 拉取社区节点 → 全量测速，API 查询与下载按测速结果择优（带总时限）；手动代理仅支持 `http://` |
| 后台常驻 | 关闭窗口最小化到托盘；托盘悬停显示程序名、上次检查时间、新版本数量 |
| 开机自启 | 写当前用户启动项，开机后在后台静默运行，不弹主界面 |
| 定时检查 | 每天自动检查一次：启动时若当天还没检查过才联网（测速 → 拉节点 → 测速 → 检查更新）；当天已检查则只展示上次结果，手动「立即检查」随时可用 |
| 更新策略 | 只通知 / 静默更新后提示 / 完全静默更新 |
| 通知方式 | 系统通知、钉钉机器人、弹出主界面（可多选，钉钉配置在同一个可展开项里） |
| 三套皮肤 | 亚克力（玻璃模糊）/ 莫奈（Material You）/ Miuix（澎湃 OS 风格） |
| 明暗模式 | 跟随系统 / 浅色 / 深色，可一键切换 |
| 毛玻璃开关 | 设置里可关闭；关闭后为不透明纯色。Miuix 皮肤不使用毛玻璃，开关会自动禁用并说明 |

毛玻璃打开时，主窗口、对话框、下拉选择菜单、右键菜单用的是同一套玻璃：
弹层出现前会先截取它背后**真实画面**再模糊，所以菜单透出来的是被它遮住的窗口内容，
而不是只贴一张壁纸；关闭开关后所有面板一起变回不透明纯色。

## 设置说明

设置页分「一般设置 / 关于」两页，所有选项都是「图标 + 标题 + 说明 + 右侧控件」的行式布局。

**用户界面**：皮肤、明暗模式、毛玻璃开关。

**后台与自动更新**
- 关闭窗口时最小化到托盘：托盘右键「退出」才真正结束程序。
- 开机自动启动：写入 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`（值名 `AutomateUpdater`），
  命令行带 `--tray`，开机后只驻留托盘。移动文件夹后重新打开一次该开关即可刷新路径。
- 定时检查更新 + 间隔：程序在后台按间隔自动扫描。
- 发现新版本时：
  - `只通知，不自动更新`（默认）—— 更新图标角标与主界面，**不弹托盘通知**，等你打开查看；
  - `静默更新，完成后提示` —— 后台直接更新，结束后发通知；
  - `完全静默更新` —— 后台更新且不打扰。
- 通知方式（可展开的一项）：系统通知 / 钉钉机器人 / 弹出主界面可多选；
  勾选钉钉后，同一张卡片里展开 Webhook 端点、加签密钥和「发送测试」。

**更新策略**
- `安装方式`：
  - `只保留指定文件夹`（默认）—— 删除名单外的旧文件，再解压新版，目录最干净；
  - `直接覆盖` —— 不删除任何已有文件，只用新版里的同名内容替换，适合压缩包里带一堆可选资源的情况。
- `默认保留的文件夹`：`User / config / data / saves / logs / profiles / 3rdparty` 一键开关（默认全开），
  下方输入框可补充自定义名字（逗号分隔）。仅在「只保留指定文件夹」模式下生效。
- 单个程序要单独定制时：列表行右键 →「更新时保留的文件夹…」，
  勾选该目录里的子文件夹（也可补充名单外的名字），还能一键「跟随全局」。
- `单个程序更新超时`：默认 10 分钟。
- `文件被占用时自动等待`（默认开启）：更新前若主程序仍在运行，或替换时检测到文件被其它进程占用，
  自动暂停并每 3 秒重试一次，行内实时显示剩余等待时间；右侧可设最长等待（默认 5 分钟），
  随时可点「停止」中断。等待超时不会误标「已最新」，该行按钮会变成「重试」。
  关闭此开关则回到旧行为：直接提示「请先关闭程序」并判为跳过。
- `覆盖前自动备份` + 保留份数：备份目录 `<根目录>\Cache\_backup\<程序名>_<时间>`。

**检查文件夹**：添加根目录后，可点「排除…」逐行填写要跳过的子文件夹；列表行右键也能直接排除某个程序文件夹。

**网络**
- `本地代理`：`自动探测`（默认，扫描常见代理端口）/ `手动指定`（下方填写代理地址）/ `不使用代理`。
  手动地址**仅支持 `http://`**（如 `http://127.0.0.1:7890`）；`socks5://` 不受支持，
  请在代理软件里另开一个 HTTP 端口，界面会明确提示。改完立即生效，不用重启。
- `GitHub 镜像加速`：内置 10 个公共镜像，默认开启。
- `每天自动测速一次`：可关；右侧「立即测速」手动并发测速全部镜像。

## 托盘

- 悬停提示：`自动化更新器 / 上次检查：x 分钟前（22:14）/ N 个程序有新版本`，
  有新版本时图标右上角带一个带白描边的红色小圆点（只提示「有待处理」，不写数字，
  这样图标能维持满幅，和别的托盘图标一样大；数量看悬停提示和右键菜单）。
- 右键菜单：打开主界面、打开设置、立即检查更新、静默更新（N）、停止当前任务、开机自动启动、退出。

## 更新是怎么做的

1. 检查：git 仓库 `fetch` 后比较落后提交数；Release 程序调用 GitHub API 取最新 tag 与压缩包。
2. 更新 Release：下载 → 解压 → 用「锚点文件」剥掉压缩包里多余的多层目录 → 备份 →
   按安装方式处理（清除名单外旧文件 / 直接覆盖）→ 写入新版。
3. 更新 git：`fetch` + `merge --ff-only`；工作区有未提交改动时不会动它，只在列表里标记「跳过」。

> 「锚点文件」指 `interface.json`、`MAA.exe`、`BetterGI.exe` 这类能标识程序根目录的文件，
> 所以压缩包是单层还是 `包名/包名/文件` 两层都能正确定位。

## 快捷键

| 快捷键 | 作用 |
| --- | --- |
| `Ctrl+1 / 2 / 3` | 首页 / 程序 / 设置 |
| `F5` | 重新检查 |
| 右键列表行 | 更新 / 绑定仓库 / 打开 GitHub 仓库 / 手动标记版本 / 保留文件夹 / 排除文件夹 |

双击列表某一行 = 打开该程序所在文件夹。
未识别到 GitHub 仓库的程序（如 `BBchannel`）会显示「未绑定」，点「绑定仓库」填入 `owner/repo` 即可启用。

## 配置文件（便携）

配置与 exe 同目录：`config.json`（目录不可写时退回 `%APPDATA%\AutomateUpdater`），
`records.json` 记录上次检查时间与程序版本，崩溃日志写到同目录 `crash.log`。
整个文件夹可以随意复制或移动到别的路径，配置跟着走。

## 更新记录

### v1.6.9

- **同一个 Release 里有多份安装包时不再猜**：像 `-full` / `-slim` / `-debug` 这种，
  以前的通用规则是「取体积最大的 Windows 包」，很容易下错。现在扫描到多个候选会把
  程序标成「待选择」，检查结束后弹窗列出每个文件的名称与体积，由你点选；选一次就记住，
  下一版文件名里的版本号变了也能对上（`v1.5.1` → `v1.5.2` 照样命中）。
  内置的 7 款程序本来就有精确正则，不受影响
- **新增「下载文件筛选（正则）」**：右键程序行 →「下载文件筛选…」，可以直接填正则，
  比如 `MAA-v.*-win-x64\.zip$`；对话框里会实时显示匹配到几个文件。优先级固定为
  **用户正则 > 列表里选中的文件 > 自动规则**，填了就严格按正则来，匹配不到会明确报错
  而不是偷偷选个别的包。已是最新的程序不会被「待选择」拦住

### v1.6.8

- **真正修掉「下到 60 多进度重置」**：GitHub API 给的 `assets[].digest` 是带算法
  前缀的 `sha256:55e919…`，而校验代码直接拿它和 `hexdigest()` 比，永远不相等。
  于是每个源都「下到 100% → 判校验失败 → 删掉 .part → 换源重下」，进度条一遍遍
  归零，最后所有源都失败。现已统一剥掉 `sha256:` 前缀（兼容 `SHA256:` / `sha256=` /
  裸 hex），认不出的格式直接跳过校验，不再误杀
- 进度条不再回退：单个程序一旦到达过的最高进度会被记住，即使真的需要重下，
  显示上也只会停住而不是从头再涨一遍
- 失败原因更准：如果所有线路里出现过「返回的不是安装包 / 大小不符 / 校验失败」，
  优先报这条，不会被最后一条线路的连接错误覆盖

### v1.6.7

- **下到一半不再换线路**：断流的判定改成「连续 20 秒一个字节都没有」，而且先在
  **当前这条线路上断点续传重试**（最多 3 次），真的续不上才换下一个加速地址。
  以前只要连接一断就直接换源，进度看着像在 60% 左右跳走、最后还判失败；现在
  只要线路还能吐数据，就会在同一条线路上接着下完
- **错误页镜像直接跳过**：测速只证明「连得通」，有些加速节点其实返回的是几百字节
  的错误页（本地实测 557 字节），以前会把它当文件写进 `.part` 再判大小不符。
  现在先比对响应头里的长度与实际大小，不对就直接换源，不产生垃圾 `.part`，也不再
  在界面上闪一下
- **失败原因写清楚**：下载失败不再只说「网络/镜像均不可用」，会显示真实原因
  （`文件大小不符（x/y）`、`HTTP 403`、`文件校验失败` 等）
- **每天只自动检查一次**：启动时先离线铺出上次的检查结果，只有当天还没检查过才
  依次执行「内置加速地址测速 → 拉取项目加速地址 → 全量测速 → 检查程序更新」。
  当天做过就直接展示上次结论，不再每次打开程序都把网络跑一遍；定时器只负责跨天
  补一次（程序常驻时次日自动检查）。手动「立即检查」/ 托盘「立即检查」不受限制
- 设置页去掉「检查间隔」下拉和「下载卡住自动切换」开关，改为固定策略 + 说明文字；
  旧的 `slow_switch` / `stall_policy` 字段升级时自动清理
- 上次检查结果存进 `records.json` 快照，离线也能看到每个程序上次是「有更新 / 最新」

### v1.6.6

- **不再因为网速低切换线路**：删掉「速度低于 X KB/s 就换源」的判定，改成可选的
  「连续 20 秒没有任何数据写入才换线路」，并且**默认关闭**。关闭时只有连接失败
  （DNS / 超时 / HTTP 错误）才会尝试下一个候选；网速慢就慢慢下，不会再把十几条
  线路挨个切一遍。需要卡住自动换源可在设置页手动打开
- **线路提示只在真正连上后出现**：`on_source` 从「尝试每个候选前」移到「连接成功、
  确认可读后」，连接失败的候选不会在界面上闪一下，不再看起来像在疯狂切节点
- 旧配置里的 `slow_switch: true`（按速度切换）升级时统一重置为 `false`；
  `min_speed_kbps` 字段不再使用，设置页的速度输入框已移除

### v1.6.5

- **不再频繁切换加速节点**：低速换源阈值默认 100 → 50 KB/s，且必须先下满 512KB 预热、
  再连续 3 个 2 秒窗口（约 6 秒）都低于阈值才切换；单次抖动或瞬间变慢不会换线路。
  旧配置里的 100 KB/s 会在启动时自动迁移为 50（之后以你在设置页填的值为准），
  连接读超时 180 → 30 秒，彻底卡死的线路也能更快换掉
  （v1.6.6 起该策略已整体替换为「默认关闭的 20 秒无写入判定」）
- **修复下载时报错刷屏**：进度刷新误把「程序列表页」当成「首页」去访问 `.list.rows`，
  每个数据块都抛 `AttributeError: 'ItemListView' object has no attribute 'list'`，
  实测 80 秒写了 2867 条 / 0.5MB 到 `crash.log`。已修正，同类异常还会按 60 秒
  合并计数写入，避免异常钩子再把日志刷爆
- **当前线路提示稳定可见**：下载进度不再覆盖状态文字，「下载中 · 线路」只在真正
  换源时变化；纯进度刷新节流到每 0.12 秒一次，阶段 / 线路提示仍即时显示

### v1.6.4

- **自动接入社区 GitHub 加速节点**：每天从
  [hubporg/ghproxy-next](https://github.com/hubporg/ghproxy-next) 的
  `components/nodes.ts` 抓取一次 `PROXY_NODES`，和手动维护的镜像一起参与测速；
  抓取走「本地代理 → 官方直连 → 按测速排序的最快加速线路」多路径回退，
  **不要求你开着 GitHub 加速**：直连不通时用内置镜像或上次缓存的社区节点转发
  `raw.githubusercontent.com`，整条回退链有 24 秒总时限；失败时保留上次节点，
  不会把可用线路清空。社区节点单独存放，不污染手动列表，设置页可开关 / 立即同步
- **镜像列表按测速结果排序**：所有候选每天测速一次，测速结果（含毫秒数）落盘，
  「GitHub 镜像地址」对话框按速度从快到慢排列，未响应的排最后并标注

### v1.6.3

- **修复 Release 类程序更新必定失败**：v1.6.1 的「回滚重试」里把异常变量命名为 `re`，

### v1.6.2

- **数值步进器可以直接键入**：设置页「单个程序更新超时」等数值框以前只能点上下箭头，
  现在点数值区或直接按数字键即可输入，回车 / 失焦提交、Esc 取消；输入过程中右侧单位
  （分钟、MB 等）始终显示，不会像旧版那样消失
- **修正「按发布时间」排序**：以前 Git 程序只有在「有更新」时才会记录远端最新提交日期，
  已是最新的一大半程序没有日期，按发布时间排时全被挤到末尾；同时「有更新最先」这条

  特殊规则只在同日内生效，选「最近发布 / 最早发布」得到的就是严格的时间顺序

## 已知限制

- `.7z` 包需要 `py7zr` 或本机安装 7-Zip；都没有时该程序会提示「解压失败」。
- 未绑定的程序（没有 GitHub 仓库）不会被更新，只做提示。
- 程序正在运行时该程序会被跳过，避免文件占用。
- 系统通知依赖 Windows 通知中心；关闭「专注助手 / 勿扰」才能看到。
- 体积排序统计的是本地目录大小（跳过 `.git`），首次扫描会略微增加耗时。
